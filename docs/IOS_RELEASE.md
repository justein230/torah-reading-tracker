# iOS release (App Store)

The counterpart of [ANDROID_RELEASE.md](ANDROID_RELEASE.md). You need a Mac with Xcode and CocoaPods
for the build; everything under "Store assets" runs on any machine.

## Names

The App Store name is **Torah Reading Tracker**. The home-screen name is the shorter **Torah Tracker**
(`CFBundleDisplayName` in `ios/App/App/Info.plist`), which fits under the icon. The mismatch is
intentional; leave it.

## Version

The app version comes from package.json, like Android's `versionName`/`versionCode`:

| Xcode setting | Shown as | Value for 1.2.0 |
|---|---|---|
| `MARKETING_VERSION` | Version (what users see) | `1.2.0` |
| `CURRENT_PROJECT_VERSION` | Build (must rise with every upload) | `10200` (major·10000 + minor·100 + patch, same packing as the Play versionCode) |

Both live in `ios/App/Version.xcconfig`, which is generated by `npm run ios:version`
(`src/utils/iosVersion.ts`, on top of the shared `src/utils/appVersion.ts`) and used as the Xcode project's base configuration; `project.pbxproj` no
longer hardcodes either. It updates itself in three places, so there is nothing to remember:

- `npm version` / `npm run release:patch|minor|major` regenerate it and add it to the version commit.
- `npm run cap:ios` regenerates it before opening Xcode.
- `tests/unit/iosVersion.test.ts` fails if the committed file doesn't match package.json.

Prereleases (`release:dev`, `release:qa`) leave the file at the last release, because App Store
Connect needs plain `X.Y.Z`. To ship 1.2.0, run `npm run release:minor`, then `npm run cap:ios`.

## One-time setup

1. Join the Apple Developer Program, then create the app in App Store Connect with bundle ID
   `com.justein.torahtracker`.
2. In Xcode, open the App target → Signing & Capabilities and pick your team (the project already
   has a development team set) with automatic signing.
3. Install dependencies once: `cd ios/App && pod install`.

## Building

```bash
npm run cap:ios
```

This runs the db/web pipeline, `cap sync`, and opens Xcode. Then choose **Any iOS Device (arm64)** →
Product → Archive → Distribute App → App Store Connect (upload). Version and build are already set
from package.json; check them on the Archive's General tab.

## Store assets

```bash
npm run db:demo -- showcase && npm run build && npm run screenshots:ios
```

Same pipeline as the Play screenshots (`scripts/screenshots.ts --platform ios`): it runs the built
app against a copy of the demo db, captures the six shots and frames each with a caption and device
mockup (`scripts/screenshot-frame-ios.html`). Output in `store/screenshots/` (gitignored):

| Folder | Size | App Store Connect slot |
|---|---|---|
| `appstore/iphone-6.3/` | 1206×2622 | iPhone 6.1" / 6.3" Display (the slot App Store Connect showed for Dynamic Island iPhones; it only takes 1179×2556 or 1206×2622) |
| `appstore/iphone-6.9/` | 1320×2868 | iPhone 6.9" Display (same images before scaling) |
| `appstore/ipad-13/` | 2048×2732 | iPad 13" Display (required because the app also targets iPad; scaled down for the 8–11" iPads) |

They are PNGs without an alpha channel (App Store Connect rejects alpha, and its uploader wouldn't take our JPEGs). The iPad shots are
captured at 820 px wide, a 10.9" iPad Air's width, so they show the real tablet layout (tab bar
instead of the bottom nav). There is no feature graphic on the App Store, but App Store Connect's "Header and Search Results"
tab takes two more assets, which the same command renders (`--only banner` for just these):

| File | Size | Slot |
|---|---|---|
| `appstore/header-5244x2950.png` | 5244×2950 (16:9) | Header (also accepts 3840×1646) |
| `appstore/search-results-3840x2560.png` | 3840×2560 (3:2) | Search Results (also accepts 5244×2950 and 1920×1280) |

Apple crops these per device and orientation, and the product page draws the icon, name, status bar,
Dynamic Island and back/share buttons over and under the header. So the artwork
(`scripts/app-store-banner.html`) has no icon or name: just the tagline and five progress bars in
a centred block, kept clear of the edges (it sits at 38% of the header's height, 50% for search
results). Use the tab's Preview button to check the crops, and move or shrink the block in that file
(`cy` in `scripts/screenshots.ts`) if anything is cut off. Upload the images in file
order: the first three show in search results.

## Listing

Drafts to paste into App Store Connect. Check the limits it shows and edit freely.

- **Name** (30): Torah Reading Tracker
- **Subtitle** (30): Track every aliyah you read
- **Promotional text** (170, editable without a new release):
  Track your Torah reading statistics. Log readings in a few taps and see your progress through all five books.
- **Keywords** (100, comma-separated, no spaces after commas):
  torah,aliyah,aliyot,parsha,parashat,chumash,pentateuch,hebrew,jewish,reading,tracker,shabbat,leyning
- **Description** (4000):

  > Torah Reading Tracker keeps a record of every aliyah you read, so you always know where you stand.
  >
  > • Overview: how much of the Torah you've read, by pseukim and by aliyot, with progress for each of the five books, a ring chart, a year-by-year chart, and a forecast for when you'll finish
  > • Grids: every parsha and aliyah at a glance, color-coded by book, with partial, scheduled and re-read markers. Shabbat, holiday and weekday readings each get their own grid
  > • Reading Log: your readings grouped by year, with the occasion and where you read
  > • Details: pseukim counts, completion percentage and last-read date for every parsha
  > • Calendar: browse your readings by date, in a month grid or an agenda
  > • Hosafot: log supplemental readings that span custom verse ranges
  > • Filters: narrow everything by book or year, or include upcoming readings
  >
  > Your data stays on your device. There is no account and no tracking, and you can back up or restore your readings from Settings.
- **Support URL**: https://docs.torah.justein.com/
- **Privacy Policy URL**: https://pages.justein.com/torah-tracker/privacy/
- **Category**: Lifestyle is already set in the project (`INFOPLIST_KEY_LSApplicationCategoryType`); Reference or Education also fit
- **Copyright**: © 2026 Justin Stein
- **App Privacy**: "Data Not Collected" (nothing leaves the device)
- **Age rating**: answer the questionnaire; the app has no objectionable content, so expect 4+
- **Export compliance**: `ITSAppUsesNonExemptEncryption = NO` is set in `Info.plist` (the app has no
  encryption of its own), so App Store Connect doesn't ask on every upload

## First submission

1. Upload the archive from Xcode, wait for processing, then add the build to **TestFlight** and
   install it on a real iPhone and iPad.
2. In the version page, add the screenshots and listing text above, pick the build, and fill the
   review notes (no login is needed to use the app).
3. Submit for review.

## Later releases

`npm run release:patch` (or minor/major), `npm run cap:ios`, archive and upload, then add the build to
the next version in App Store Connect and submit.
